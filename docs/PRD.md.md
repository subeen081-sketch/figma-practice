# [PRD] 의정부시청 대표홈페이지 「행사·축제」 서비스 UI/UX 개선

> 작성 기준: 「행사·축제 서비스 UI/UX 개선 최종 보고서」에 수록된 내용만 반영했습니다. 근거가 부족한 항목은 **"추가 확인 필요"**, 디자인 세부 사항은 **"세부 스펙은 다음 단계에서 확정 예정"**으로 표시했습니다.

---

## 1. 문서 개요 (Document Overview)

### 1.1 프로젝트 목적
- 시민이 행사·축제 정보를 **포스터 카드 단계에서 바로 인지**하고, 목록·상세·전화 문의까지 **막힘없이 이어서 이용**하도록 개선한다.
- 그리드/리스트 보기 전환 **오작동(그리드 버튼 클릭 시 텍스트 목록 출력)을 복구**하고, 웹 접근성(KWCAG 2.2) 및 KRDS 기준을 준수한다.

### 1.2 개선 범위
- 메인 포스터 카드 및 목록의 정보 구조 개편
- 그리드/리스트 보기 전환 기능 복구 및 상호작용 개선
- 명칭 통일, 상세 화면 정보 재배치, 액션 수단(전화·길찾기·공유) 강화
- 탐색 맥락 보존(검색 조건·쪽 번호·보기 방식 유지)

### 1.3 목표 (사전 설정 가설)
> "그리드 뷰 전환 오작동 및 명칭 불일치로 인한 조작 오류 횟수를 0회로 줄이고, KWCAG 2.2 및 KRDS 검증 항목 100% 준수를 통해 행사·축제 정보 탐색 과업 성공률 100%를 달성한다."

### 1.4 우선순위 (테마별)
| 우선순위 | 테마 | 비고 |
|---|---|---|
| **P1 (Must-Fix)** | 서비스 일관성 및 보기 방식(뷰) 인터랙션 | 전환 오작동 복구, 접근성 규격 준수가 선행 과제 |
| P2 | 탐색 및 검색 경험 | 정렬·필터·검색 맥락 유지 |
| P3 | 시민 중심의 목록·카드 정보 구조 | 카드 일시·장소, 표 가독성 |
| P4 | 상세 정보 재배치 및 액션 실행성 | 포스터 상단 배치, 전화·길찾기 |

## 3. 핵심 사용자 여정 (Core User Journey)

### 3.1 일반 시민
1. **진입**: 대표 명칭 "행사·축제"와 서브 탭으로 현재 위치 인지
2. **보기 선택**: 그리드 버튼 클릭 → 포스터 카드 정상 노출 (호버 시 "그리드 보기" 툴팁)
3. **비교·탐색**: 카드 하단의 일시·장소로 즉시 비교, 페이지 이동 후에도 그리드 보기 유지
4. **상세 확인·완수**: 상세 상단 포스터·핵심 정보 확인 → 전화 걸기/길찾기/공유 → [목록으로] 복귀 시 기존 조건 유지

### 3.2 시각장애인 시민
1. **위치 파악**: 스크린 리더가 대표 명칭 "행사·축제"를 안내
2. **보기 전환**: 버튼의 이름과 선택 상태(`aria-label`, `aria-pressed`)를 음성으로 안내받아 조작
3. **연속 탐색**: 정렬·쪽 변경 후에도 선택한 보기 방식 유지, 초점 논리적 보존
4. **완수**: 스크린 리더만으로 행사 정보를 독립 탐색

## 5. UI/UX 및 정책 요구사항 (UI/UX & Policy Requirements)

### 5.1 공공언어 가이드라인
- **대표 명칭은 "행사·축제"로 통일**하며, 이와 다른 명칭("한눈에 달력" 등)은 화면에서 사용하지 않는다.
- 버튼·툴팁 문구는 시민이 바로 이해하는 쉬운 표현을 사용한다. 자료에 명시된 문구는 "그리드 보기", "리스트 보기", "목록으로", "길찾기", "전화 걸기", "총 00건"이다.
- 상태 표기는 접수중/진행중/마감을 사용한다.
- **확인 필요 사항**
  - 시각 레이블("그리드 보기")과 `aria-label`("그리드 형태로 보기")의 표현이 서로 다르다. KWCAG 2.2 6.5.3(레이블과 네임) 취지상 일치 여부 검토가 필요하며, 최종 문구는 **추가 확인 필요**.
  - 원문의 "과절된 행사" 표현은 의미가 불분명하여, 종료 행사로 해석했으나 **추가 확인 필요**.
  - 공공언어 가이드(순화어·표기 기준) 적용 검수 결과는 자료에 없음 → **추가 확인 필요**.

### 5.2 시각적 우선순위
- **카드/목록**: 포스터 → 분야·제목 → 일시·장소 → 상태 배지 순으로 인지되도록 구성한다. 순서 확정은 다음 단계.
- **상세 화면**: 행정용 표를 아래로 내리고, 포스터와 핵심 정보(일시·장소·문의처)를 최상단 영역에 좌우 배치한다(모바일은 수직 배치).
- **목록 표**: 제목 열을 가장 넓게 확보하고 번호·부서는 축소한다.
- **상태 배지**: 색상만으로 구분하지 않고 텍스트를 병기한다. 방향은 접수중(청색), 진행중(녹색), 마감(회색)이며 **색상 코드는 다음 단계에서 확정 예정**.

### 5.3 레이아웃 규칙
| 항목 | 규칙 |
|---|---|
| 모바일 기준 | 360px(KRDS Small Breakpoint), 콘텐츠 너비 348px (마진 16px, 가터 16px, 4칼럼) |
| 터치 타겟 | 모든 버튼·뷰 전환 아이콘 최소 44px × 44px |
| 카드 | 모바일 1열 반응형 (Reflow) |
| 모바일 상세 | 하단 [전화 걸기]/[길찾기] 고정 바 |
| 아이콘 | KRDS 시스템 아이콘 표준 격자/리스트 형태 |
| 접근성 | 아이콘 단독 사용 금지(레이블/툴팁 병행), 포스터 `alt` 제공, 초점 순서 논리적 유지 |

위 수치는 와이어프레임 반영 사항 기준이며, 데스크톱 레이아웃 세부 규칙은 자료에 없어 **추가 확인 필요**입니다. **세부 스펙은 다음 단계에서 확정 예정**입니다.

### 5.4 준수 기준
- KWCAG 2.2: 지침 5.1(대체 텍스트), 6.5.3(레이블과 네임)
- KRDS: 목록 탐색, 필터링·정렬, 상세 정보 확인, 컴포넌트(표·링크·아이콘·버튼), 디자인 원칙 6
- 닐슨 사용성 휴리스틱 (문제별 매핑은 보고서 2장 참조)

## 반응형

### 기본 원칙
- 모바일 우선(Mobile First)으로 작성한다. 기본 스타일은 모바일 기준이며, 큰 화면은 min-width 미디어쿼리로 확장한다.
- 반응형 상세 디자인은 구현 단계에서 사이즈별 Figma 링크로 전달한다. 이 섹션은 공통 기준만 정의한다.

### 분기점
| 구분 | 범위 | 비고 |
|---|---|---|
| 모바일 | 360px ~ 767px | 기본 스타일 |
| 태블릿 | 768px ~ 1439px | 모바일 레이아웃을 확장, 필요 시 단 수·배치 조정 |
| 데스크탑 | 1440px ~ | 데스크탑 레이아웃 |

- 360px 미만 화면에서도 가로 스크롤 없이 콘텐츠가 깨지지 않아야 한다.

### 콘텐츠 너비
- 데스크탑에서는 콘텐츠 영역에 최대 너비(max-width: 80rem)를 지정하고 가운데 정렬한다. 화면이 넓어지면 양옆 여백이 늘어난다.
- 배경색·배경 이미지 등 전체 폭 요소는 화면 끝까지 채우고, 내부 콘텐츠만 최대 너비를 따른다.

### 단위 규칙
- 레이아웃은 상대단위(%, rem)로 구성하고, 고정 px 너비는 지양한다.
- em 단위는 사용하지 않는다.
- 루트 글자 크기는 브라우저 기본값(1rem = 16px)을 유지하고, html에 고정 px 글자 크기를 지정하지 않는다.
- 분기점(미디어쿼리)과 테두리 두께(1px 등)는 px 사용을 허용한다.

### 접근성
- 뷰포트 메타 태그에서 사용자 확대를 막지 않는다(user-scalable=no, maximum-scale=1 사용 금지).
- 화면을 200%까지 확대해도 내용이 잘리거나 겹치지 않아야 한다.
- 버튼·링크 등 터치 대상은 최소 2.75rem(44px) × 2.75rem 크기를 확보한다.

### 요소별 처리
- 주메뉴(GNB): 모바일·태블릿에서는 전체메뉴 버튼 방식으로 전환하고, 데스크탑에서는 펼친 메뉴로 표시한다. 세부 형태는 Figma를 따른다.
- 표: 좁은 화면에서 표 영역만 가로 스크롤되도록 처리하고, 페이지 전체가 가로로 넘치지 않게 한다.
- 이미지·미디어: 부모 너비를 넘지 않도록 max-width: 100%를 적용하고 비율을 유지한다.

### 6.3 가설 판단 및 해석상 유의점
- **보고서 판단**: 계속(Persevere) – 가설 채택 및 유지
- **유의점 (추가 확인 필요)**
  1. 표본이 5명이고 Peer 평가자로 구성되어 있어, 일반화 가능성은 제한적이다.

  4. 카드 정보 인지, 전환 오류 등 개선 전(As-is) 대비 정량 비교 수치는 자료에 없다.
